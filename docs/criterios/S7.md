# S7 · Reportes — Criterios de aceptación

Versión 1.1 (10-oct-2026) · Escrito en WF-0 por el agente «criterios»; corregido en la ronda 1 de revisión (ver `INDICE.md` §9) · El revisor de backend (WF-3) evalúa **solo** contra este archivo. Convención de evidencia, severidades y comandos: ver `INDICE.md`.

## 1. Objetivo
Entregar `backend/internal/reportes`, las plantillas `.tex` y `backend/internal/telegram`: resumen diario y semanal por Telegram (Axel y Ximena), reporte mensual PDF en LaTeX el día 1, estado de cuenta de Karen en PDF bajo demanda, vista web mensual y las 4 alertas, con cifras idénticas a las de la API.

## 2. Criterios

**S7-01 (alta) · El reporte mensual compila.** La plantilla del reporte mensual compila con `lualatex` sin errores ni referencias indefinidas y produce un PDF abrible.
- Verifica: `cd <directorio de build del agente> && latexmk -lualatex -interaction=nonstopmode -halt-on-error <reporte>.tex; echo $?` = 0; `grep -c "^!" <reporte>.log` = 0; `grep -c "undefined" <reporte>.log` = 0; `pdfinfo <reporte>.pdf` imprime `Pages:` ≥ 1; `pdftoppm -r 60 -png <reporte>.pdf /tmp/s7-pag` genera una imagen por página.
- Evidencia: reporte del agente §Verificación línea `S7-01` con las salidas.

**S7-02 (alta) · Cifras del PDF = API (cruce automático).** Un script o prueba automática extrae todas las cifras monetarias y las fechas del PDF (`pdftotext -layout`) y las compara con las respuestas de la API del mismo periodo: **0 diferencias**. La fixture del oráculo (despensa del 10-oct, periodo P1 = oct-2026) muestra devengado 1,947.50, efectivo 973.75 y diferencia acumulada 973.75 (R-45); P1–P6 (oct-2026…mar-2027) coinciden con R-45…R-50 de `S2.md` (nota (e) de su sección 6).
- Verifica: `go test ./internal/reportes/... -run Cruce -count=1 -v` (el agente puede nombrarlo distinto y lo declara); salida esperada: M de M cifras iguales, 0 diferencias, M ≥ las cifras visibles del PDF (el reporte lista M).
- Evidencia: línea `S7-02` con M y la lista de campos cruzados.

**S7-03 (alta) · Estado de cuenta de Karen.** Se genera en PDF **bajo demanda**; contiene solo la despensa en común y las compras particulares de Karen con el crédito Kueski (su parte: para la despensa 1, 1,499.72 con intereses 308.22, 374.93 por quincena en 30-oct, 15-nov, 30-nov y 15-dic-2026); no contiene ingresos de Axel ni finanzas de la familia de Karen; compila y su cifras cruzan con la API como en S7-02. El sistema **no lo envía a Karen**: Axel lo reenvía a mano.
- Verifica: `go test ./internal/reportes/... -run Karen -count=1 -v`: el PDF de la fixture de despensa 1 trae R-10, R-11, R-12 y las 4 fechas de R-13…R-16; `pdftotext` no contiene la cadena del ingreso quincenal de Axel; la lista de destinatarios de cualquier aviso rechaza a Karen.
- Evidencia: línea `S7-03`.

**S7-04 (alta) · Resumen diario y semanal por Telegram.** El resumen diario sale de noche y el semanal el domingo, a Axel y Ximena, con cifras tomadas **solo del motor/API** (ninguna cifra fija en la plantilla). El contenido concreto de cada resumen y su hora exacta no están en el plan: si no están escritos en el reporte del agente y aprobados por Axel, es el bloqueo `criterios-umbrales-ausentes` y quedan PROVISIONAL.
- Verifica: `go test ./internal/reportes/... -run Resumen -count=1 -v` con fecha simulada (noche de un día cualquiera; domingo): cada resumen se genera una sola vez y su texto coincide con la API.
- Evidencia: línea `S7-04`.

**S7-05 (alta) · Texto plano y formato Telegram.** Los mensajes se envían como **texto plano, sin `parse_mode`**; encabezado en mayúsculas; ningún mensaje supera el límite de la API de Telegram para texto (el agente cita el valor vigente de la documentación oficial); los nombres con guiones bajos (p. ej. archivos) no rompen el mensaje.
- Verifica: `go test ./internal/telegram/... -count=1 -v` con un servidor `httptest` que registra la petición: el cuerpo no contiene `parse_mode`, contiene `chat_id` y `text`; un texto con `reporte_mensual_2026_10.pdf` llega íntegro; un mensaje largo se divide.
- Evidencia: línea `S7-05`.

**S7-06 (alta) · Token y credenciales.** El token del bot MultiX se lee **en ejecución** desde `~/.openclaw/openclaw.json` y jamás se imprime, registra, copia al repositorio ni aparece en pruebas o capturas. Las pruebas usan un archivo de configuración falso y un servidor falso.
- Verifica: `grep -rn "[0-9]\{8,10\}:[A-Za-z0-9_-]\{30,\}" /home/deepsec/finanzas-hogar --include=* -I` = 0 coincidencias; prueba que captura stdout/stderr/logs de un envío y no encuentra el token del archivo falso. Cómo llega el token al servicio cuando corra con usuario propio (`finanzas`) y el archivo esté en el home de otro usuario no está decidido: es el bloqueo `criterios-token-servicio`.
- Evidencia: línea `S7-06`.

**S7-07 (alta) · Envío real con HTTP 200.** El envío real al chat de Axel por el bot MultiX devuelve HTTP 200 y el mensaje es visible. **Lo ejecuta el orquestador** (los agentes no mandan Telegram: protocolo §7); el agente de S7 deja el comando de disparo manual (resumen diario y una alerta de pago) y lo prueba contra el servidor falso. El envío a Ximena depende de que ella escriba una vez al bot MultiX (acción de Axel, plan §8.2): hasta entonces queda «pendiente de acción» y no se declara verificado.
- Verifica: el orquestador dispara el resumen diario y una alerta de pago (plan §9 punto 4) y registra código HTTP y confirmación visual de Axel.
- Evidencia: `docs/estado/wf3/<orquestador>.md` línea `S7-07` (HTTP 200 por cada mensaje) y la confirmación de Axel; Ximena marcada pendiente si aplica.

**S7-08 (alta) · Las cuatro alertas disparan en fixtures de fecha.** (1) Pago próximo: el día anterior **y** el mismo día; (2) presupuesto al 80 % y al 100 % (categoría y total); (3) precios viejos antes del día de despensa; (4) plan de comidas sin armar (domingo). Con el calendario del oráculo: pago del 2026-10-30 → alertas el 2026-10-29 y el 2026-10-30 y ninguna el 28 ni el 31; febrero de 2027: pago del 28 → alertas 27 y 28. Cada alerta se dispara **una vez** por su disparador y periodo (sin duplicados por reintento). La anticipación exacta de (3) y la definición de «sin armar» de (4) no están en el plan: si no están escritas y aprobadas, es el bloqueo `criterios-umbrales-ausentes` y quedan PROVISIONAL.
- Verifica: `go test ./internal/reportes/... -run Alerta -count=1 -v`: matriz de fechas × alertas con disparos esperados y no esperados; 0 diferencias.
- Evidencia: línea `S7-08` con la matriz.

**S7-09 (alta) · Destinatarios configurables.** Cada aviso tiene sus destinatarios configurables en Ajustes (Axel y Ximena); un destinatario sin `chat_id` registrado se omite y se reporta (no falla el resto); Karen no puede ser destinataria.
- Verifica: `go test ./internal/telegram/... -run Destinatarios -count=1 -v`: Axel y Ximena con chat, Ximena sin chat (se omite, el de Axel sale), intento de agregar a Karen (rechazado).
- Evidencia: línea `S7-09`.

**S7-10 (alta) · Reporte mensual el día 1.** El job del día 1 genera el PDF mensual, lo **guarda** en disco (versionado por mes) y lo envía por Telegram a los destinatarios configurados; si LaTeX falla, el job queda en error visible y no se envía un PDF parcial.
- Verifica: `go test ./internal/reportes/... -run Mensual -count=1 -v` con reloj simulado al 1 de noviembre de 2026 (America/Mexico_City): PDF creado, ruta guardada, envío al servidor falso con `sendDocument`; con una plantilla rota, estado `error` y 0 envíos. El tamaño del PDF se reporta y no excede el límite de `sendDocument` de la documentación oficial de Telegram (valor vigente citado por el agente).
- Evidencia: línea `S7-10`.

**S7-11 (alta) · Vista web mensual.** Existe un endpoint de C1 y una pantalla de U1 para la vista web mensual, con las mismas cifras que el PDF del mismo mes (cruce automático, 0 diferencias).
- Verifica: `go test ./internal/reportes/... -run VistaMensual -count=1 -v`; el endpoint aparece en `openapi.yaml` y en la matriz pantalla ↔ endpoint de U1.
- Evidencia: línea `S7-11`.

**S7-12 (alta) · Formato de dinero, fechas e idioma.** En PDF, mensajes y vista: dinero como `$1,234.56` (MXN, dos decimales, separador de miles), fechas `10-oct-2026` (con día de semana, `Vie 30 oct 2026`, donde importe); es-MX únicamente; ninguna fecha ISO ni texto en inglés visible.
- Verifica: prueba que aplica a todos los textos generados las expresiones `^\$-?[0-9]{1,3}(,[0-9]{3})*\.[0-9]{2}$` para cada cifra monetaria y `[0-9]{4}-[0-9]{2}-[0-9]{2}` (0 coincidencias en texto visible); lectura de 10 líneas por el revisor.
- Evidencia: línea `S7-12`.

**S7-13 (media) · Estilo del PDF.** Los colores de las plantillas salen de los tokens de C2 (no se copian a mano de la paleta del reporte previo, que Axel descartó); el texto cumple contraste ≥ 4.5:1 sobre su fondo, calculado con el mismo script de U2; tipografía instalada localmente.
- Verifica: `grep -n -i "definecolor" <plantillas .tex>` y comparar cada hex con `docs/contratos/C2-tokens.json`; cálculo de contraste de cada par texto/fondo.
- Evidencia: línea `S7-13`.

**S7-14 (media) · Sin red salvo Telegram; calidad.** `internal/reportes` no hace llamadas de red; `internal/telegram` solo al host de la API de Telegram; LaTeX y `pdftotext` por `exec` local con tiempo límite; `go vet` limpio; cobertura de `reportes` y `telegram` medida y reportada; sección SUPUESTOS.
- Verifica: `cd /home/deepsec/finanzas-hogar/backend && go vet ./internal/reportes/... ./internal/telegram/... && go test -cover ./internal/reportes/... ./internal/telegram/...`; `grep -rn "http://\|https://" internal/reportes internal/telegram --include=*.go | grep -v _test.go` solo muestra el host de Telegram.
- Evidencia: línea `S7-14`.

## 3. No aceptable
- Cifras del PDF, del mensaje o de la vista que no salen de la API; valores fijos en las plantillas.
- Mensajes con `parse_mode` (Markdown/HTML); token impreso en cualquier lugar; token copiado a un archivo del repositorio.
- Mandar Telegram desde un agente; marcar el envío real como verificado sin código HTTP 200 y sin confirmación visual.
- Estado de cuenta de Karen con datos de otras personas o enviado automáticamente a ella; Karen como destinataria.
- Alertas que se disparan en fechas no esperadas o más de una vez por el mismo disparador.
- PDF con errores de LaTeX ignorados; PDF parcial enviado; colores copiados de la paleta descartada.
- Fechas ISO o inglés en texto visible; dinero sin dos decimales.
- Horarios, contenidos, anticipaciones o definiciones inventados sin marca PROVISIONAL.

## 4. Umbrales numéricos (del plan)
- PDF compila sin errores: 0 errores de LaTeX (S7-01).
- Cruce automático: 0 diferencias de cifras (S7-02, S7-11).
- Envío real: HTTP 200 (S7-07).
- Alertas: pago próximo día anterior + mismo día (2); presupuesto 80 % y 100 % (2 umbrales × categoría y total); precios viejos; plan sin armar domingo → 4 alertas (S7-08).
- Frecuencias: diario (noche), semanal (domingo), mensual (día 1).
- Destinatarios: 2 (Axel, Ximena); Karen 0 (S7-09).
- Contraste texto ≥ 4.5:1 (S7-13).
